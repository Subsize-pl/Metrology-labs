# Лабораторная работа № 2а — метрики Джилба и Маккейба (Java)

Графический анализатор рассчитывает **абсолютную сложность CL**, **относительную
сложность cl** и **максимальный уровень вложенности CLI** по метрике Джилба для
любого исходного текста на Java. Дополнительно выводится цикломатическое число
Маккейба Z. Анализируемая программа — `NumberReport.java` (99 строк).

## Состав

| Файл | Назначение |
|---|---|
| `NumberReport.java` | анализируемая консольная программа: все циклы Java, `if`/`else if`/`else`, `switch`, подпрограммы |
| `GilbAnalyzer.java` | парсер и расчёт метрик (javac Compiler Tree API + один обход дерева) |

| `GilbReport.java` | текстовый расчёт «как вручную» и консольный отчёт |
| `GilbAnalyzerApp.java` | окно (Swing) и консольные режимы |
| `GilbAnalyzerTest.java` | проверки: примеры методички, все виды операторов, switch, граничные случаи, 400 случайных программ |
| `overview.pdf` | одна страница: правила, результат для эталонной программы, поведение в крайних случаях |
| `result.png` | снимок окна с результатом — для отчёта |
| `Отчет_ЛР2а_Java.docx` | отчёт: титульный лист, код, схемы алгоритма по ГОСТ 19.701-90, ручной расчёт, скриншот |
| `scheme/` | схемы алгоритма каждой подпрограммы в SVG — исходники рисунков отчёта (Word: «Вставка → Рисунки», затем «Преобразовать в фигуру») |

## Требования

- JDK 21 или новее (нужен именно JDK: используется модуль `jdk.compiler`);
- сторонние библиотеки **не нужны**.

## Сборка и запуск

Из каталога `lab2a-gilb-mccabe`:

```bash
javac --release 21 -encoding UTF-8 -d build GilbOptions.java GilbMetrics.java GilbAnalyzer.java GilbReport.java GilbAnalyzerApp.java GilbAnalyzerTest.java NumberReport.java

java -cp build GilbAnalyzerApp                             # окно; NumberReport.java открывается сам
java -cp build GilbAnalyzerApp Other.java                  # окно с указанным файлом
java -cp build GilbAnalyzerApp --analyze NumberReport.java # то же в консоли
java -cp build GilbAnalyzerTest                            # проверки (-v — подробно)
java -cp build NumberReport 4 7 -2 9 6 abc                 # сама анализируемая программа
```

Флаги консольного режима: `--no-loops`, `--ternary`, `--no-declarations`, `--blocks`
(те же переключатели есть в окне). `--screenshot <file.java> <out.png>` сохраняет
снимок окна для отчёта.

В окне результат пересчитывается сам через 0,3 с после любой правки текста;
строки с ветвлениями подсвечены (янтарный — `if`, синий — циклы, зелёный — `case`),
щелчок по строке таблицы «Ветвления» переходит к ней в коде.

## Правила подсчёта

Источники: методичка `МетрикиПотокаУправления.pdf`, страница курса «Задание 2» и
документация языка (JLS, гл. 14; Java Tutorial, «Expressions, Statements, and Blocks»).

| Величина | Как считается |
|---|---|
| **CL** | сумма ветвлений: каждый `if` (в т. ч. каждый `else if`), каждый цикл (`for`, `for-each`, `while`, `do-while`), каждая метка `case` |
| **N** | число операторов Java по JLS, гл. 14 (не по Холстеду): объявления локальных переменных, выражения-операторы, `if`, `switch`, циклы, `break`, `continue`, `return`, `throw`, `try`, … |
| **cl** | `CL / N` |
| **CLI** | наибольшее число ветвлений, внутри которых лежит ветвление; не вложенное — 0 |
| **Z** | `CL + 1` для каждой подпрограммы, сумма по подпрограммам (граф с одним входом и выходом: `e − v + 2`) |

**switch.** Заменяется цепочкой вложенных `if`: метка `case` — одно условие, селектор и
`default` условием не считаются. Для `switch` из n ветвей получается n − 1 условий и
вложенность n − 2 (рис. 2–3 методички). Оператор(ы) в ветке лежат внутри соответствующего
`if` цепочки, `default` — последний `else`.

**Что не является оператором:** объявления классов, методов, полей и параметров;
скобки `{ }`; заголовок `for` (он часть оператора); `catch`/`finally` (части `try`);
метки `case`/`default`; тело лямбда-выражения без скобок.

### Проверка на примерах методички

| Пример | Ожидается | Получено |
|---|---|---|
| рис. 3 (цепочка из 4 `if`, N = 11) | CL = 4, cl = 0,36, CLI = 3 | совпадает |
| рис. 2 (switch из 5 ветвей) | CL = 4, CLI = 3 | совпадает |

## Поведение в крайних случаях

| Ситуация | Что делает анализатор |
|---|---|
| Пустой текст, только комментарии | N = 0, CL = 0, CLI = 0; cl показывается как «—» |
| Нет ветвлений | CL = 0, CLI = 0, cl = 0 |
| Не весь файл (метод без класса, набор операторов) | сам оборачивает в класс/метод; режим разбора виден в строке состояния |
| Синтаксические ошибки | числа считаются по восстановленному дереву, выводится число ошибок и первая из них; программа не падает |
| Ключевые слова в комментариях, строках, текстовых блоках, именах | не учитываются (разбор настоящим парсером) |
| `else if` | каждый `if` — ветвление, каждый следующий на уровень глубже |
| Висячий `else` | относится к ближайшему `if` |
| `switch` без `default`, с одним `default`, пустой | CL = числу меток `case`: 0 меток — условий нет |
| Стопка меток (`case 1: case 2:`) и `case 1, 2 ->` | каждая метка — условие |
| `switch`-выражение, образцы, `case null, default` | ветвления считаются как у `switch`-оператора; само выражение в N не входит |
| `default` не последний | его тело всё равно последний `else` цепочки |
| `for (;;)`, `while (true)` | цикл есть цикл: +1 |
| `int a = 1, b = 2;` | один оператор (JLS 14.4) |
| `for (int i = 0, j = 5; …; i++, j--)` | один оператор `for`: инициализация и обновление — его части |
| Лямбды, анонимные и локальные классы | операторы в них считаются, вложенность — по тексту |
| Тернарный `?:`, `&&`, `\|\|`, `catch` | ветвлениями не считаются (`?:` можно включить) |
| Файл с BOM, CRLF, Windows-1251 | читается корректно |
| Очень длинный и очень глубокий код | 20 000 строк и вложенность 1 500 обрабатываются; анализ идёт в потоке с большим стеком |

## Схемы алгоритма

Каждая подпрограмма изображена отдельной схемой по ГОСТ 19.701-90: «Терминатор», «Процесс»,
«Предопределённый процесс» (вызов подпрограммы), «Данные» (вывод), «Решение». `switch` в
`dayName` нарисован цепочкой из четырёх вложенных ветвлений, `default` — последняя ветвь
«Нет». Цикл — символ «Решение» с возвратом потока на проверку условия; `try/catch` — пунктирный
альтернативный путь, ветвлением не считается.

На всех схемах 18 символов «Решение» — по одному на каждое ветвление, поэтому CL = 18 можно
проверить подсчётом ромбов. Метка «№k · ур. L» у ромба — номер ветвления и уровень вложенности
из таблицы выше.

## Допущения, которые стоит подтвердить с преподавателем

1. **Объявления** (`int x = 0;`) считаются операторами. Если нужны только «действия»,
   снимите флажок — N уменьшится, cl вырастет.
2. **Блоки `{ }`** не считаются операторами. Если нужно по грамматике JLS — включите флажок.
3. **Циклы** входят в CL по тексту страницы «Задание 2»; в самой методичке (PDF) CL
   определён как «количество условных операторов». Рис. 1 методички считает условие цикла
   ветвлением (CL = 2), поэтому по умолчанию циклы входят.
4. **Рис. 1 методички** даёт CLI = 1, потому что на схеме вершина 4 стоит на ветке «нет»
   вершины 2. В тексте программы `while` и следующий за ним `if` идут друг за другом,
   и вложенность равна 0.
